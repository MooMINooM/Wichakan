# Teacher assignment roster

The page uses the shared Wichakan header and shell, followed by year/term/grade/room filters, three summary cards, a separate homeroom strip, and a full-width subject table. No duplicate assignment sidebar is rendered. Row actions open an accessible dialog.

The baseline is the selected year's latest effective version of each curriculum, using the same `curriculumCourses` helper as the school dashboard. Each registered subject is shown for every selected room, including subjects without a course offering. “Assigned” means at least one stored teaching assignment exists in the selected term; co-teachers share one row. With multiple rooms, counters use “รายการ” and explicitly state that counts are per room.

Existing offerings outside the selected catalog remain visible with a “รายวิชาเปิดสอนเดิม” label so their assignments can still be managed. Unavailable or inactive teacher accounts are identified without fabricating profile names. Only active teacher members are available for new assignments. Catalog/assignment read failures display an error and unknown metrics rather than a false zero or complete status. Reads are paginated in stable order; profile IDs are fetched in batches.

New subject assignments use the existing `assign_teacher_to_subject` RPC, which checks school role, teacher membership, and classroom/term/grade compatibility and creates an offering if needed. Homeroom add/remove and subject removal retain school-scoped writes and RLS. Removing a teacher requires confirmation in the dialog. Multiple homeroom teachers and subject co-teachers remain supported; changing teachers consists of explicitly removing/adding the desired assignments. An unsuccessful save retains the chosen teacher. A successful write followed by a failed refresh reports the saved result and the refresh error separately.

Validation: `node tests/teacher-assignment-rows.cjs`, existing school-readiness tests, TypeScript, and a production static build. Mocked browser coverage checks 8 subjects (5 assigned / 3 missing), two-room totals and pagination, >1,000 assignment records, unoffered-subject creation, co-teacher removal, homeroom changes, filters/search, year/term/grade isolation, failed-save retention, failed-load retry, read-only roles, and mobile overflow. Production schema/RPC access checks were read-only; no real teaching or homeroom assignments were modified.
