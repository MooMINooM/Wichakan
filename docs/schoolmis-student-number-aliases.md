# SchoolMIS: รหัสนักเรียนเดิมไม่ตรงกับรหัส WICHAKAN

**หลักการ:** ใช้รหัสนักเรียนที่สถานศึกษายืนยันใน `public.students.student_no` เป็นรหัสหลักของระบบ ส่วนรหัสในไฟล์ SchoolMIS ที่ไม่ตรงกันต้องเก็บแยกเพื่ออ้างอิงย้อนหลัง และห้ามแก้รหัสหลักโดยอัตโนมัติ

## โครงสร้าง
- `public.schoolmis_student_number_aliases`: mapping `school_id,source_student_no → student_id` (จำกัดสิทธิ์อ่านเฉพาะ Admin/งานทะเบียนของโรงเรียน, ไม่มีสิทธิ์เขียนผ่าน public Data API)
- `public.schoolmis_grade_history.source_student_no`: รหัสที่ปรากฏใน CSV เดิม ควบคู่ UUID นักเรียนที่ถูกจับคู่
- ฟังก์ชันนำเข้า `schoolmis_import_history`: ตรวจ UUID นักเรียนและรหัสปัจจุบันก่อน, หาก source ID ต่าง ต้องมี alias ที่ได้รับการตรวจสอบและไม่ซ้ำกับรหัสหลักของผู้อื่นภายในโรงเรียน
- UI นำเข้า: แสดงรหัสที่จับคู่ต่างกัน ตรวจชื่อ–สกุลทุกครั้ง และส่งต้นฉบับ `source_student_no` พร้อมรหัสหลัก `student_no`

## ความปลอดภัยและข้อมูล
- การเพิ่ม alias จริงต้องทำด้วยการยืนยันตัวบุคคลและดำเนินการในฐานข้อมูลโดยเจ้าหน้าที่เท่านั้น ไม่มีหน้าเพิ่ม alias แบบเปิดให้ผู้ใช้ทั่วไป
- ไม่ commit รหัสและชื่อจริงของนักเรียนใน SQL migration หรือประวัติ Git
- ตัวอย่างเชิงรูปแบบ: SchoolMIS=เลขเก่า A, WICHAKAN=เลขใหม่ B ให้เก็บ mapping A→นักเรียน UUID ของ B แทนการเปลี่ยน B เป็น A
- ห้ามจับคู่โดยใช้เพียงชื่อ–สกุล, เพราะอาจมีคนชื่อเหมือนกัน ต้องตรวจห้องเรียน ปีการศึกษา และการยืนยันจากโรงเรียนด้วย
- บันทึกคะแนนของครูในปีปัจจุบันไม่ได้รับผลกระทบ

## การตรวจสอบ
- import ซ้ำด้วย source ID เดิมสำหรับระเบียนที่มีอยู่แล้วต้องได้ `unchanged=1` และ `imported=0`
- import ด้วย source ID ของ alias ที่อ้างนักเรียนคนอื่นต้องปฏิเสธ `schoolmis_student_alias_not_authorized`
- ไม่แก้ประวัติผลการเรียนเดิมหรือคะแนนปัจจุบันด้วยการสร้าง alias
